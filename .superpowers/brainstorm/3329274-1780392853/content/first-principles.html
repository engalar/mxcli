canonical model 是不归路。重新定义问题，找最小成本解。

✓ 关键洞察

gen builder 已经是单一正确的写路径。它把 MDL 输入正确转化为 BSON。describe 读 BSON 输出 MDL。漂移只发生在 BSON→MDL 的格式化层——而这已经通过 propInt、列宽渲染器、footer 提取等修复了。

问题从来不是"缺少 canonical model"，而是"describe 格式化器有 bug"。

第二步：canonical model 究竟解决了什么？
我们原本想解决的
  • entity/association 有 canonical model → page 也应该有（一致性）
  • describe 路由统一走 ModelCodecs → 所有域统一分发
  • Hydrate 能从 gen Page 提取完整 widget 树
⚠ 实际代价
  • WidgetNode 平铺结构 → 3 文件各 1000+ 行 switch（SOLID 问题）
  • PluggableWidget → MPK schema + TypePointer 引用链约束
  • RawType + RawObject → modelsdk 缓存和按需加载的冲突
  • widgetNodeFromGen → 每个 gen widget 类型的 typed getter 适配
  • AugmentTemplate 集成 → MPK 版本兼容性

这是复杂度爆炸的根源：页面 IR 比 entity/association 复杂 10 倍，因为 widget 是开放扩展的插件体系。

第三步：最简解——两个不变式 + 一层守护测试

不变式：gen builder 是唯一的写真相

1 写路径不变：execCreatePageV3 → gen builder → BSON。不需要 canonical Persist，不需要 widget 级 canonical model。gen builder 已经写对了。
2 读路径守住 BSON：describePage 对于复杂页面走 raw BSON 路径（已有 lossy fallback），对于简单页面走 IR 路径（IR-1~5 已修复）。不需要引入新的复杂中间层。
3 漂移守护：写一个 Round-trip 测试——MDL → create → describe → 对比输出是否可以重新 parse。这是检测漂移最直接的方式。
第四步：最小化改动清单
✗ canonical model 方案（放弃）
• PluggableWidget IR + RawType + RawObject
• widgetNodeFromGen（适配20+种 gen 类型）
• AugmentTemplate 集成
• WidgetCodec Registry（每族一个 codec）
• 替换3个1000行 switch
• modelsdk cache 机制协调

代价：数千行新代码，3-6个月工作量，引入新的失败模式

✓ 最简方案（推荐）
• 保留现有 gen builder 写路径（不动）
• 保留 raw BSON describe 路径（不动）
• IR-1~5 已修复的列宽/footer（已完成）
• PageDocument stub 满足 canonical 接口（已完成）
• 新增：round-trip 守护测试（~50行）
• 新增：修复 describe 遗留 bug（按需）

代价：极小，守护已有功能，不引入新复杂性

第五步：round-trip 守护测试设计
// mdl/executor/roundtrip_page_test.go

// 守护测试：确保 MDL → create → describe 的输出可以无损重执行
func TestPageRoundTrip_NoMDLDrift(t *testing.T) {
    cases := []struct{ name, mdl string }{
        {"simple dataview", `create or replace page M.P layout Atlas.Default () {
  layoutgrid lg { row r1 {
    column c1 (DesktopWidth: 12, TabletWidth: AutoFill) {
      dataview dv (datasource: $MyEntity) {
        textbox tb (attribute: Name)
      }
    }
  }}
}`},
        // 更多 case...
    }

    for _, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            // 1. 写入
            ctx := newIntegrationContext(t)
            requireNoError(t, ctx.Execute(tc.mdl))

            // 2. 读回
            described := captureDescribe(ctx, "M.P")

            // 3. 验证可重解析（关键：不是字符串相等，而是语义等价）
            requireNoError(t, ctx.Execute(described))  // 重执行不报错

            // 4. 二次 describe 必须与第一次相同（幂等）
            described2 := captureDescribe(ctx, "M.P")
            assert.Equal(t, described, described2, "describe 不幂等")
        })
    }
}

一句话总结

gen builder 写对了，describe 读 BSON 的格式化 bug 已修。最简解：加 round-trip 幂等测试守住这个不变式，不需要 canonical page model。 PageDocument stub 留在注册表里满足架构一致性即可——它永远不会被 Persist 调用，Hydrate 是只读辅助。
