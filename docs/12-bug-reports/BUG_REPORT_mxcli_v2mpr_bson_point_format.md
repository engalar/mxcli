# Bug Report: mxcli writes invalid Point/Size BSON format for Mendix 11 MPR v2

## Summary

When `mxcli exec` creates new microflows or pages in a Mendix 11.6.6 MPR v2 project (mxunit-based), the generated `.mxunit` files store `RelativeMiddlePoint` and `Size` property values using space-separated format (`"200 200"`, `"20 20"`). Mendix Studio Pro and `mx check` expect semicolon-separated format (`"200;200"`, `"20;20"`). This causes the project to fail to load entirely with a `StorageLoadException`.

## Environment

- **mxcli version**: current (as of 2026-05-19)
- **Mendix version**: 11.6.6
- **MPR format**: v2 (mxunit-based, `mprcontents/` directory)
- **Platform**: Linux (Ubuntu 22.04)

## Steps to Reproduce

1. Open a Mendix 11.6.6 project in MPR v2 format (with `mprcontents/` directory).
2. Verify project loads cleanly:
   ```bash
   ./mxcli docker check -p project.mpr
   # Expected: project loads, reports N errors
   ```
3. Create any new microflow via `mxcli exec`:
   ```sql
   create or modify microflow MyModule.ACT_Test ()
   returns Nothing
   begin
     return;
   end;
   /
   ```
4. Re-run the check:
   ```bash
   ./mxcli docker check -p project.mpr
   ```

## Actual Result

```
ERROR: Mendix.Modeler.Storage.StorageLoadException: One or more invalid values were detected while loading the project:
 - Start event in microflow 'MyModule.ACT_Test' has an invalid value '200 200' for property RelativeMiddlePoint. Invalid Point: 200 200
 - Start event in microflow 'MyModule.ACT_Test' has an invalid value '20 20' for property Size. Invalid Size: 20 20
```

The project fails to load completely. All subsequent `mx check` / `mxcli docker check` calls fail.

## Expected Result

The generated `.mxunit` file should store `RelativeMiddlePoint` as `"200;200"` and `Size` as `"20;20"` (semicolon-separated), matching the format used by Studio Pro and existing mxunit files.

## Root Cause Analysis

Inspecting the generated `.mxunit` file (raw BSON) confirms that mxcli writes point values as space-separated strings. Existing mxunit files in the same project (generated by Studio Pro) use semicolon-separated format.

**mxcli generates:** `"200 200"` (BSON string, 8 bytes)  
**Studio Pro expects:** `"200;200"` (BSON string, 8 bytes — same length, different separator)

The BSON string length is identical (both are 7 chars + null = 8 bytes), so a simple in-place byte substitution (space → semicolon) can fix already-generated files without changing any BSON document lengths.

## Workaround

After any `mxcli exec` that creates new objects, run the following Python script to fix all new mxunit files:

```python
import os, struct, hashlib, base64, sqlite3, re

def fix_mxunit_points(fpath, mpr_path):
    with open(fpath, 'rb') as f:
        raw = f.read()
    data = bytearray(raw)
    changes = 0
    i = 0
    while i < len(data) - 10:
        if i + 4 < len(data):
            str_len = struct.unpack('<I', data[i:i+4])[0]
            if 3 <= str_len <= 20:
                potential = data[i+4:i+4+str_len-1]
                try:
                    s = potential.decode('ascii')
                    m = re.match(r'^(\d+) (\d+)$', s)
                    if m and data[i+4+str_len-1] == 0:
                        new_s = f'{m.group(1)};{m.group(2)}'
                        new_bytes = new_s.encode('ascii') + b'\x00'
                        assert len(new_bytes) == str_len
                        data[i+4:i+4+str_len] = new_bytes
                        changes += 1
                except (UnicodeDecodeError, AssertionError):
                    pass
        i += 1
    if changes > 0:
        with open(fpath, 'wb') as f:
            f.write(bytes(data))
        new_hash = base64.b64encode(hashlib.sha256(bytes(data)).digest()).decode()
        fname = os.path.basename(fpath).replace('.mxunit', '').replace('-', '')
        unit_id = bytes.fromhex(fname)
        conn = sqlite3.connect(mpr_path)
        conn.execute('UPDATE Unit SET ContentsHash = ? WHERE UnitID = ?', (new_hash, unit_id))
        conn.commit()
        conn.close()
    return changes
```

## Affected Operations

Any `mxcli exec` statement that creates new objects:
- `CREATE [OR MODIFY] MICROFLOW`
- `CREATE [OR REPLACE] PAGE`
- `CREATE SNIPPET`
- `CREATE ENUMERATION` (with positioned elements)

## Priority

**High** — the project becomes completely unloadable after any `mxcli exec` in MPR v2 format. The workaround requires running a Python post-processing script after every exec.

## Suggested Fix

In the mxcli BSON serialization layer, change the Point/Size string formatter from space-separated (`"%d %d"`) to semicolon-separated (`"%d;%d"`) to match what Mendix Studio Pro 11 writes.
