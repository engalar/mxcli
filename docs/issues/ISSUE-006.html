问题描述

SEM-03 实现过程中经过多轮修复，但多次没有使用 mx check 作为权威验证，导致：

  • 某次修复（消假阳）引入了另一个假阳性问题，又要再修
  • 使用自建调试测试替代 mx check，误判了正常行为
  • 过度修复（如 numericCompat）实际上恰好是正确的，但需要 mx check 才能确认
  • 总体导致多轮反复，影响了代码质量的信心

根本原因
  • SEM-03 使用自建集成测试（TestSEM03_Macnica_HasDetections）作为验证——但"有检出"不等于"检出正确"
  • 基线测试只检查了"有无 SEM-03 结果"，没有检查"结果是否正确"（即是否与 mx check 一致）
  • 假阳性的发现依赖于手工运行 bin/mxcli，而不是系统化的 mx check 对比
  • 多次修复没有先分析根因，而是直接尝试修改代码
已建立的工作流程规则
分析优先 任何修复前，先与用户一起分析根因并获得批准，再写代码
mx check 为权威 每次代码修改后，必须运行 mx check 对 macnica 和 Mx2026AIDay 两个应用进行验证
原子性提交 每次只修改一个根因，独立 commit，便于问题定位和回滚
双向验证 修复需同时满足：macnica 新增真阳性 AND Mx2026AIDay 仍为 0 errors
Issue 先行 新发现的问题先记录在 docs/issues/，确认理解后再修复
