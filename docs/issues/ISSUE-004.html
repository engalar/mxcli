背景：已修复的部分

提交 3384d440 修复了 BSON 字段名错误：

  • "Parameter" 字段包含 "Module.MFName.ParamName"（3段），之前代码误读不存在的 "Microflow" 字段
  • 修复后：128 个 MicroflowCallParameterMapping 槽位的 CalleeQN 从 0% 解析提升到 100%
  • 但 mismatch 仍为 0
当前问题

128 个参数映射槽位已解析 CalleeQN 和 ParamName，但对应的参数类型查询（idx.MicroflowParamKind(calleeQN, paramName)）可能返回 KindUnknown。

mx check 报告 3 个 Call microflow 活动的 CE0117：

[CE0117] at Call microflow activity 'SUB_AdvanceStepStatus'
[CE0117] at Call microflow activity 'SUB_RemoveApprovalWaiting'
[CE0117] at Call microflow activity 'ACT_WorkHistory_Regist'

可能的根因：

  • 根因 A：这 3 个微流的参数类型在 mfParamKinds 中未被索引（如参数是 Enumeration 类型，但 elementToKind(*genDt.EnumerationType{})→KindEnumeration 是否正确？）
  • 根因 B：传递的参数表达式推断为 KindUnknown（表达式太复杂无法静态推断）
  • 根因 C：被调用的微流是系统微流或跨模块微流，未被 ListMicroflowsGen() 索引
需要验证的问题
  • 这 3 个微流（SUB_AdvanceStepStatus 等）是否在 mfParamKinds 中有记录？
  • 出错的参数名称是什么，声明类型是什么？
  • 传递的实参表达式是什么，推断类型是什么？
  • BSON 中的参数声明 VariableType.$Type 是哪种类型？
修复方向（待批准）

此 issue 影响仅 3 个错误，优先级低于 ISSUE-001 和 ISSUE-002。在解决高优先级 issue 后再处理。

可能的修复：

  • 若参数类型是 Enumeration 且 elementToKind 未正确处理 → 补充处理
  • 若是跨模块微流索引问题 → 改进 buildMicroflowVars 覆盖所有模块
  • 若是表达式推断问题 → 依赖其他 issue 的修复（ISSUE-001/002）
