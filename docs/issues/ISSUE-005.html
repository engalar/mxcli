问题描述

在消除假阳性时（commit 396431bb），将 numericWiden()（单向拓宽）改为 numericCompat()（所有数值类型双向兼容），以消除 Mx2026AIDay 中 28 个 round()/ceil()→Integer 的假阳性。

疑问：这是否让 Decimal→Integer 等本应报错的赋值也被放行？

验证方法

运行 mx check（Mendix 官方编译器）对两个应用进行权威检查：

~/.mxcli/mxbuild/11.6.6/modeler/mx check "Factory Management.mpr"
→ The app contains: 0 errors.  ✓

~/.mxcli/mxbuild/11.6.6/modeler/mx check MacnicaApp.mpr
→ 44 CE0117（无 Decimal→Integer 相关）
验证结论
✓ numericCompat() 是正确的
场景numericCompat 放行mx check 结果结论
round($x) → Integer 属性
Mx2026AIDay 中 28 例		 ✓ 兼容 0 errors（mx check 接受） 正确放行，非错误
Decimal → Integer 变量
运行时截断		 ✓ 兼容 mx check 接受 Mendix 允许此类转换
Long → Integer 变量
可能溢出		 ✓ 兼容 mx check 接受（运行时截断） 与 mx check 一致

Mendix 在编译时不检查数值类型精度丢失，允许所有数值类型之间的隐式转换。numericCompat() 与 Mendix 的行为一致。

✓ numericCompat() 无需修改。macnica 的 44 个 CE0117 漏报原因不在此处，而在 ISSUE-001（$id 未索引）等其他根因。
