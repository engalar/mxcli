初始假设（已证伪）
✗ 初始假设：id 是未被索引的 Long 型实体属性，加入 entityAttrs 即可推断 $Entity/id 为 KindLong。

实际情况： 1. id 在 Mendix 中是保留字，既不能创建也不能在表达式中读取。 2. 这些 $Var/id 中的 $Var 全部是 KindList（kind=9），不是 KindObject。 3. 错误根因是"在 List 变量上做属性访问"，与类型不匹配（SEM-03）无关。
确认的根因

macnica 中存在大量以下模式：

// RetrieveAction（Retrieve All）返回 List
$PayerSalesAreaData : List of Customer_Common.PayerSalesAreaData

// ChangeVariableAction 试图读取 id
Change variable PayerSalesAreaDataId ← $PayerSalesAreaData/id  ← CE0117

两个独立的问题叠加：

  1. id 是 Mendix 保留字：在表达式中不能读取任何实体的 id 属性（包括单对象的 $Entity/id）
  2. 在 List 上访问属性：$ListVar/attr 在 Mendix 中是非法的——必须先 FirstItem 或使用 Aggregate，才能访问单个对象的属性

这两点都不是 SEM-03（类型不匹配）的范畴，而是表达式语法/语义错误。

当前检测结果和原因

目前 mxcli 对所有这些案例输出 0 个错误。推断链路：

$PayerSalesAreaData/id
→ AttributePathExpr { Variable="PayerSalesAreaData", Path=["id"] }
→ inferAttrPath:
    cat.EntityQNOf("PayerSalesAreaData") = "Customer_Common.PayerSalesAreaData"  ← 返回 entityQN（即使是 List 也会）
    cat.AttributeKind("Customer_Common.PayerSalesAreaData", "id") = (KindUnknown, false)
→ 返回 KindUnknown → Compatible(Unknown, Integer) = true → 跳过 → 漏报

即使我们加入 id → KindLong 到索引：

cat.AttributeKind("Customer_Common.PayerSalesAreaData", "id") = (KindLong, true)
→ 推断出 KindLong
→ 目标变量 PayerSalesAreaDataId 是 Integer
→ Compatible(Long, Integer) = true (numericCompat)  ← 仍然漏报！
即使我们修复了 id 索引，numericCompat 仍会放行 Long→Integer（已被 mx check 验证为正确行为）。所以这条路根本走不通。
正确的错误检测方向

这类错误需要一个新规则（暂称 SEM-08 或 SEM-L01），独立于 SEM-03：

检测规则：当 AttributePathExpr 的 Variable 在当前作用域内为 KindList 时，报告错误"不能在 List 变量上访问属性，需要先使用 FirstItem"。

独立的 id 保留字规则：检测 AttributePathExpr.Path[last] == "id"，报告"id 是 Mendix 系统保留字，不可在表达式中读取"。

这两条规则可以在 inferAttrPath 之前的检查层（SEM-07 所在的验证层）实现，而不是 SEM-03 类型检查层。
