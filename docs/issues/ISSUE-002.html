根因分析 — 最可能的解释

假说 A（最可能）：Cascade 错误

macnica 中有 19 个 Change variable CE0117（ISSUE-001 的对象）。如果这些 ChangeVariable 错误导致某个变量的类型在 Mendix 编译器内部被标记为"无效"，那么同一微流中后续使用该变量的 Log message 活动也会被标记 CE0117。

ℹ Mendix 的 CE0117 是传播式的：上游表达式错误会导致下游使用该变量的所有活动也产生 CE0117。
一旦 ISSUE-001 修复后 ChangeVariable 错误消失，这 7 个 Log message CE0117 可能会一并消失。

假说 B（次要）：LogMessageAction/Node 字段未扫描

我们未扫描 LogMessageAction/Node 字段。该字段有 2 个非字面量表达式（getKey()），经确认合法。但可能还有其他 Node 表达式未被发现。

此假说最多解释 2 个 CE0117，不能解释全部 7 个。

假说 C（已排除）：TemplateParameter 类型推断失败

最初的 ISSUE-002 描述认为是"推断失败导致 KindUnknown"。调查发现这不正确：全部 96 个表达式成功推断为 KindString，没有类型不匹配。
