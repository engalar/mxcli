## §1 Background — Status Snapshot

The pages domain is the **single largest** of the six Stage 3.3 domains:

- **41 in-scope importers** + 16 sdk/mpr Stage 4 files = 57 total
- **1478 LoC** legacy sdk vs **34,483 LoC gen types** (the largest gen package)
- **232 gen types** (vs 71 for domainmodel, 92 for workflows)
- **~50+ widget types** spread across 5 sdk files (action/advanced/container/data/display/input)
- **api/pages.go (821 LoC, 70 sdk refs)** — public API surface, requires §14 user approval
- **page_mutator.go (1575 LoC)** — already raw-bson (like workflow_mutator); only signature migration needed
- **datagrid_builder.go (1287 LoC)** — heavy DataGrid2 builder logic
- **widget_engine.go + widget_property.go** — pluggable widget templates (CE0463 risk per CLAUDE.md "Pluggable Widget Templates")

### Master plan §8.4 special considerations (REPEATED)

1. **Widget tree mutator** (`OpenPageForMutation`) is already in `mdl/backend/mpr/page_mutator.go` — Phase D follows existing pattern (signature change only, raw-bson logic stays).
2. **Pluggable widget templates** (CLAUDE.md "Pluggable Widget Templates"): CE0463 "widget definition changed" risk if Object/Type schema diverges. Stage 3.3.5 D-phase round-trip tests MUST run `mx check` against pluggable widget fixtures (DataGrid2, ComboBox, Gallery).
3. **50+ widget types** = large flat fanout — family formatters per widget category (input/display/list/container/action/advanced).
4. **`ALTER PAGE/SNIPPET` complexity** — most write-path commits will be here.

### Already migrated — DO NOT redo

- `mdl/backend/mpr/mf_page_modelsdk.go` — small bridge for microflow/page references (`PageClientAction` resolution).
- `mdl/executor/cmd_security_write_page_gen.go` — Stage 3.3.1 helper that grants/revokes page access via gen security path; uses `sdk/pages` only for `pages.AllowedRoles []string` (a plain string slice, not the rich page types).

| # | Risk | Impact | Mitigation |

| R3 | **CE0463 pluggable widget definition mismatch** — DataGrid2/ComboBox/Gallery need exact Type+Object roundtrip | Critical | Phase D round-trip tests run `mx check` on fixtures with each pluggable widget. Reuse `sdk/widgets/templates/` infra; gen `CustomWidget` carries raw template via opaque getters |
| R4 | **Page mutator already raw-bson** (like workflow_mutator) — only signature migration. The mutation logic stays | Low — proven pattern from Stage 3.3.3 D7 | Phase D7 reuses workflow_mutator.go pattern |
| R5 | **DataGrid2 builder (1287 LoC)** — heavy column/header/filter logic. Migration must preserve every column property | High — silent grid corruption | Phase D8 dedicated task; round-trip test on a fixture grid with all column types |
| R6 | **AllowedRoles version-prefix** — already-fixed Stage 3.3.1 D6a; verify Page round-trip emits correct shape | Medium | Phase D2 round-trip test |
| R7 | **Container ID resolution for nested widgets** — gen Page has Widget tree; container lookup is by walking the tree, not by SQL Unit table (widgets are NOT separate units; they live inside a Page unit) | High — different lookup pattern from microflows | Helper `findWidgetInPageGen(page, name)` walks the tree via `page.WidgetsItems()` recursively; mirrors legacy `findWidget` |
| R8 | **DataSource polymorphism** — `DatabaseSource`, `XPathSource`, `MicroflowSource`, `AssociationSource`, `ListenTargetSource`, `ContextSource`, `EmptySource`. ~7 types | High | Phase A `formatDataSourceGen` family formatter; each type 1 commit |
| R9 | **ClientAction polymorphism** — `CallMicroflowClientAction`, `CallNanoflowClientAction`, `NavigateToAction`, `ShowMessageAction`, `OpenLinkAction`, `RunUntilTerminationAction`, `SaveAction`, `CancelAction`, `CloseAction`, etc. ~15 types | High | Phase A `formatClientActionGen` family formatter; group by category (microflow/nano/page/edit) |
| R10 | **Stage 4 boundary at sdk/mpr** (16 files — most of any domain) | High coordination cost | E3 strictly conditional; deprecation header escape hatch |
| R11 | **Cross-domain consumers**: mermaid, styling, CRUD page builders. Migration touches non-pages files | High blast radius | Phase C separates per-consumer file. cmd_pages_builder_v3.go (53 refs) is the densest — own commit |
| R12 | **Theme registry / styling** — `cmd_styling.go` (551 LoC, 11 refs) reads page theme classes. Migration mechanical but must preserve theme override behavior | Medium | Phase C7 dedicated task |

| R14 | **Snippet calls** — Pages can embed `SnippetCall` widgets that pass parameters to Snippets. Param resolution depends on snippet's parameter list (cross-page-type dependency) | High | A0 verifies SnippetCall accessors; helper resolves param mapping |
